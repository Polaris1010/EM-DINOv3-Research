# Pilot C后续研究建议：一次固定100k配对终点

状态：DESIGN_ONLY。用户本轮只要求研究建议，明确不启动新训练；所有既有任务仍停止。本文件不构成训练授权。

## 决定

建议给当前固定Barrier配置一次完整的100k配对检验。分别恢复C0/C1现有45k完整状态，各继续55k至100k，然后用匹配的原版Primus40k评价。完成后决定保留或结束该配置，不增加系数搜索、延迟启用变体或其他loss。

这修正了C-2报告中的“当前配置不继续作为MICCAI主线”建议。45k的性能负结果全部保留；建议修正的原因是该终点尚未覆盖历史100k严重退化阶段，长期稳定性问题仍待匹配终点回答。

以上均为同一decoder seed20261014，复用已有结果。

- Pilot B显示早晚权重有可利用的互补性：中点恢复肌肉、提高MB-1均值，并保留部分后期收益。这支持继续检验训练阶段稳定性约束，但没有指定Barrier一定有效。
- C-2直接测得45k的代价：肌肉Dice−0.075061、AP−0.051623、Recall−0.090534；Turner Dice−0.064686。C1在7/12开发来源及6/7 MB-1组提高，表现是来源间权衡，并非所有来源统一受损。
- C0/45k肌肉Dice与30k接近，远端FP仍低；Primus AP已经下降0.043198。严重Dice/FP退化在现有100k结果中出现，45k不足以检验其防止效果。

待检验假设：早期约束代价能否在更长训练后换来较好的任务表现。该假设与“当前45k没有净收益”可以同时成立。官方DINOv3也将Gram anchoring用于长训练的密集特征退化问题；本轮继续使用已锁定的自定义Barrier，不新增官方Gram项。背景文献：[DINOv3原论文](https://arxiv.org/abs/2508.10104)。

## 唯一建议实验

1. **复用两份45k full checkpoint。** 从已登记的C0/C1完整状态分别恢复student、EMA、optimizer及各rank RNG，接续各自轨迹。资产定位与SHA见[artifact_hashes.json](../evidence/Pilot-C2/artifact_hashes.json)。C1仍锚定原D2/30k EMA，不把anchor改成45k。
2. **两组各继续55,000步，固定终点100k。** 延续历史100k LR/WD函数、数据/增强序列、batch48和既有RNG协议；lambda1、margin0.05、bottom50%、Chebyshev>2、Layer23及生产模式保持。独立新目录，旧控制器固定45k/18h，不能直接重启替代新预算执行器。GPU0继续禁用。
3. **只在固定100k做正式下游比较。** 两个新EMA分别训练新Primus40k，seed20261014、TTA OFF；沿用Linear23 500步作为读出说明，完成38dev及MB-1七组。45k的head不接到新encoder上。中间恢复点只用于容错，不根据MB-1选checkpoint；不以Linear AP取消Primus。

主要对照为C1/100k−C0/100k。历史D2/100k和Pilot B中点保留为参照；重新续训C0可保证本轮完整数据/RNG/日程配对，不仅将C1与历史100k相比。

## 如何作最终决定

首先报告100k的绝对性能差：肌肉Dice、AP、Recall与远端FP；同时报告MV3/MB-1来源等权均值及全部来源损益，重点解释Turner、HeLa、OpenOrganelle的代价或收益。再比较与中点的实用权衡，不要求所有来源同时领先。

附报45k→100k的变化差：`(C1_100k−C1_45k)−(C0_100k−C0_45k)`。该量不能独立判成功：C1在45k起点已经较差，必须同时看100k相对C0的绝对质量。远端FP下降也不能替代Dice/AP和Recall。

- 若C1在100k获得有价值的肌肉Dice/AP收益，同时保留多来源能力，并对中点形成有价值的权衡，继续把它作为候选方法，随后才考虑重复性与必要方法消融。
- 若仍主要降低Recall、造成Turner等损失，且没有相对配对C0及中点的实际收益，结束当前固定Barrier配置；不再以“可能更晚有效”为由延长或搜索lambda。
- 若新C0没有复现历史100k严重退化，按实际100k结果评价新增loss，长期防遗忘解释继续保留为未证实；不以复现失败为理由追加诊断链。

即使成功，masked/DropPath student与unmasked eval anchor的差异仍限制机制归因。MB-1是已经暴露的开发压力诊断，GT只评分，不用于选择参数。

## 计算预算与停止

按C-2实际15k时长线性外推：C0新增55k约11.91h，C1约12.82h，SSL串行合计约24.73h、使用三卡约74.19 GPU-hours。加两组并行head及同规模完整评测，名义墙钟约26.03h，排程可预留26–30h。这是基于实测吞吐的估算，尚未执行。
