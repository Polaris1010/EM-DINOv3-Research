# 决策：先做两组短程持续预训练

用户在明确获知来源关联门槛后批准探索，并授权自行选择继续适配或重做 P1。本轮选择复用已核验 P1，进行同预算 TJ / TM 对照；暂不重做长程 P1。

- GPU 1：TJ，现有 JRC 图像池，10k 次 SSL 更新。
- GPU 2：TM，现有31个 MitoVerse train 体积，10k 次 SSL 更新。
- GPU 3：继续已启动的 P1 seed2 全体积开发测试；完成后领取下游 probe 队列。
- 两组同为 batch16、global256、local112×8、Gram 权重0；保留原额外教师分支。SSL heads 使用相同seed的新初始化，编码器从P1初始化，新建优化器。
- 严格身份审计并未通过。独立记录探索例外，不清空原隔离清单，不宣称无泄漏或完全未见域。
- SSL不按标注或mask筛选图像；按来源、体积、切片/裁剪分层抽样。
- 独立短测含第10步checkpoint与第11步连续参考；恢复到第11步后逐项比较参数、优化器、随机状态及样本消费链。通过才从P1重新开始500步前缀，再完整恢复至10k。
- 仅最终10k EMA进入下游；每组3个head seeds各10k，复用相同修复后的监督采样清单及head初始权重。验证选择分割head，不反向修改SSL预算。

选择理由：现有低分来自冻结编码器probe，尚不能将问题定位为P1预训练不足。短程成对实验能区分额外SSL收益与目标数据适配收益，预算比直接重做长程P1更小。若有明确收益，再讨论长程预训练；当前没有效果提升结论。

正式协议：exploratory_ssl_protocol.lock.json；来源例外：exploratory_ssl_authorization.json；运行状态：exploratory_ssl_status.json。资源限制及网站保护保持不变，最多三个GPU任务，不使用GPU0。
